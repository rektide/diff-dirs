| Multiple-destination replacement command | Planned integration; the public command has not switched to it. N2 must not be implemented by calling N1 repeatedly. |
| Durable JW continuation | Not used by this callable route. JW uses the cursor in-process and fails forward; library persistence remains separately available. |

The consumer selects real ignored source directories. It preserves native S/D
leaves, administrative roots and link-owned paths; discovers viable selected
descendants through routing directories; and mirrors admitted interiors. If the
entire qualifying source root disappears, its target remains. Source absence
*inside* an admitted region can authorize deletion. Empty selection avoids the
ordinary runtime altogether. Those are JW semantics, not generic library defaults.

## Demonstrated help

- The production kernel replaces private copying/removal machinery while retaining
  required reflinks, coupled replacements, logical paths, timestamp/mode handling
  and joined cleanup. Native identity and tree-state adoption remain in JW.
- Pure early/late policy makes streaming authority possible without a separate
  payload eligibility walk or native subprocesses inside callbacks.
- `Container::CreateIfNeeded` answered a concrete consumer need: search missing
  source-only routes without creating unmatched target skeletons. Its generic
  container effect is owned by the library; wildcard/ignoredness decisions stay
  with JW. Existing required-CoW tests cover this adoption.
- Historical large-workload observations support preserving unchanged auxiliary
  payload instead of rewriting it. Two older matched N2 runs fell from roughly
  99–108 seconds to 18–21 seconds while preserving existing payload inodes. These
  are **older pair-adapter results**, not measurements of today's coordinated route.

## Where the fit is incomplete

**The sharing domain is narrower than the whole refill.** Common paired directories
share source observations. Source-only copy, conditional routing and replacement
interiors still recurse separately per receiver. Tracked `seed_leaves` work also
observes/opens source leaves per destination. Cold or mixed-shape receivers may
therefore expose much less sharing than a clean paired payload.

**The live cursor pays for capabilities JW does not currently use.** Exact decisions
are eagerly projected and cloned alongside live plans; clean normal groups still
enter the application barrier. Comparison and application separately check routes,
including repeated source ancestry/canonicalization. Policy prefix/ignore queries
also repeat per lane. These are source-visible costs, not measured bottleneck rankings.

**Retained equality is not a sharing certificate.** The ordinary predicate retains
equal type/size/mtime files. That alone establishes neither distinct source/target
inodes nor shared physical extents. New reflink installations are a different
result. If JW promises to repair privacy or sharing on an equal leaf, the library
needs explicit effect authority: ordinary `InstallLeaf` currently requires an
observed difference. Do not falsify the baseline comparison to request a reclone.

| Direction | Owner | Evidence that would justify it |
| --- | --- | --- |
| Lighter live execution: defer checkpoint projection, reduce duplicate decision views and avoid proven effect-free dispatch | diff-dirs; same observation/frontier/kernel | Real N1 clean/deep-route CPU, allocations and route-call census, retaining coverage and control semantics. `planned == 0` alone is not an effect-free proof. |

| Share source batches for opaque source-only/replacement deliveries | diff-dirs transfer execution | N2 both-missing and paired/missing cases show material repeated source cost; independent target effects/permissions/failure remain correct. |
| Reuse a validated tracked-leaf batch/index | JW supplies native membership; generic installation may expose reusable input | Demonstrate avoidable per-receiver rebuilding/sorting/acquisition without weakening strict installation. |
| Reuse compiled prefix and frozen-ignore queries | JW first | Deep wildcard-route policy CPU/allocation evidence; no mutable decision-order dependence or new payload census. |
| Opportunistic independently advancing cohorts | Library, if needed by real consumers | Heterogeneous lane wait/memory evidence outweighs the current barrier's simplicity. Stopping a lane is not suspension. |

Native command reduction, prepared-source identity, tracked sharing renewal, desired
revision selection and operator history/preview semantics belong to JW. The most
recent human clarification keeps **renew donor sharing as the tracked-file baseline**:
determining whether existing files already share storage may be expensive or lack
usable evidence, particularly given the compressed/inline checksum limitations.
The engineering task is to make required renewal efficient, with the existing native
route as a control. Optional sharing detection must justify its own correctness,
coverage and cost before it can eliminate installs. See the
[renewal rationale and performance evidence](/design/architecture/annealing0.gpt6ax.md#annealing-native).
This clarification concerns tracked renewal; retained ordinary payload still has
the separate stat-equality and storage-evidence contract described above.

The human also selects support for **clear-then-populate and authorized replacement
without initial clearing**, followed by benchmarking. Both renew donor sharing
proactively; the second route need not perform equality or sharing detection.
Clearing's original appeal was a simple population policy over available tracked
destinations. The alternative needs explicit target-replacement authority and a
truthful native transition while sharing the command inputs and production kernels.
The [two-route design](/design/architecture/annealing0.gpt6ax.md#two-proactive-renewal-routes)
connects this requirement to inherited intent and separates it from choosing a winner.
