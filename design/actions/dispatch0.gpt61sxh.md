# Finite parameterized dispatch with owned pending work

## Recommendation

**Start with caller-typed `Work` and ordinary `match` dispatch. Add a finite
`{kind, version, parameters}` adapter at a real stored/external boundary, not a
global registry. Both must enter the same checked publication path.** Flexible
actions mean typed goals and parameters, not extending physical add/change/remove
with opaque commands or allowing a KV payload to bypass ownership checks.

The isolated model in `.test-agent/action-dispatch/` passes **11 tests**. It binds
two actual meanings—settle source-file bytes and install a generated report—and a
small copy-children → report composite. Ten tests use model effects; one anchors
real copying, generated bytes, after-visible-output retry and wrong-kind refusal.
The scratch implementation is ignored; this document is the committed return.

## 1. The smallest useful boundary

These are recommended application-level shapes, not production/core APIs:

```rust
enum Work {
    SettleSourceLeaf(CopyInput),
    InstallReport(ReportInput),
}
struct Target { root: RootId, relative: OwnedRelativePath }
struct Selected<W> { work: W, claims: Vec<Claim>, dependency: Position }
struct Request<W> { ticket: Ticket, position: Position, work: W }

fn validate_typed(selected: Selected<Work>, bindings: &BindingContract)
    -> Result<ValidatedUnit>;
fn bind_descriptor(raw: Descriptor, bindings: &BindingContract)
    -> Result<ValidatedUnit>; // decode known schema, then validate_typed
fn dispatch(pending: &ValidatedPending, runtime: &mut Runtime)
    -> Attempt<Settled>;
fn acknowledge(ticket: Ticket, reply: Reply, saved: &mut Saved)
    -> Result<()>;
```

`ValidatedUnit`/`ValidatedPending` are private checked wrappers, **not serialized
authority**. Restoration reconstructs and validates them. The full driver owns
phases, child suffixes and component state; dispatch only selects the implementation
of the current unit. The probe uses a fixed sequence position rather than another
DFS driver. Its composite exposes all three leaf destinations immediately, keeps
the report reservation while copies run, and makes accepted child count a finish
input. No DAG scheduler or recursive executor is needed.

| Choice | What it buys | Limit / decision |
| --- | --- | --- |
| Caller `enum Work`, typed parameters, direct `match` | Compile-time payload shape, visible semantics and ordinary application construction; codec-free owned continuation is possible. | New handler means updating the application's enum/match. This is sufficient for the tested scenarios. |
| Finite versioned descriptor → typed work | Stored/configuration/independently produced jobs can select known families without exposing Rust layout. Unknown input has a defined refusal boundary. | A semantic version and payload validator are necessary. A finite match/function supplied by the caller is enough. |
| Global discovery, plugin ABI or open registry | Independently loaded executable families. | Not required or probed. Registration would not prove write footprints, restartability or generated-name admission. |

Generic `Work<P>` or an application-supplied dispatch function is also reasonable;
do not force every consumer into one globally growing enum. Executable handlers
are supplied again on bind, not saved as closures, downcasts or shared singleton
objects. Ordinary in-memory use need not construct raw descriptors or serialize.

## 2. Concrete descriptor and handler responsibilities

The probe's raw envelope is `Descriptor { id, kind, version, parameters: Value }`
plus separately declared claims. `parameters` is a KV object **only until typed
decoding**. Supported family/version pairs are finite:

| Kind/version | Typed parameters and meaning | Runtime responsibility |
| --- | --- | --- |
| `settle-source-leaf/1` | Physical source `{source-A, relative}`, explicit target `{target-A or reports-A, relative}`, `ExactRegularBytes`. Source and destination routes may differ. | Read the actual good source bytes; acquire target kind/bytes; settle the declared target only. No descent, deletion, metadata preservation or type replacement. |
| `generated-report/1` | Explicit generated origin `{producer: summary, version: 1, logical}`, target, label, count input, chosen content mode and byte rule. Count is supplied input for a standalone report or accepted children for composite finish. | Render `label:count:ordinal\n`, or install already chosen owned bytes; acquire target kind/bytes independently of physical differences. No fake physical source. |
| `copy-then-report/1` | One to seven source-leaf descriptors followed by one report descriptor using `AcceptedChildren`. No nested composites. | Pure finite expansion only. The driver issues children in order, waits for their acknowledgments and then derives report input. The composite handler does not execute children. |

All fields affecting output, target selection, source identity, satisfaction and
dependency interpretation are part of the bound contract. Struct payloads reject
unknown fields; missing fields, wrong types, unknown rules, escaping routes,
unrecognized producers and unsupported kind/version refuse. A handler version is
an **interpreter/meaning version**, not just a syntax revision. The probe's saved
schema 1 additionally freezes its typed enum meanings. Semantic changes require
an explicit version/migration choice, never silent fallback to a current handler.

An application may retain inert annotation KVs in a distinct namespace, but they
must not secretly affect writes, dependencies or output. This probe instead
rejects an added `shell` key. There is no shell/subprocess payload or arbitrary
key lookup at execution. This is intentional finite data-driven dispatch, not a
weakly typed plugin framework.

The entire small composite is decoded and validated **before its first effect**,
including its later child and finish. Unknown second-child version therefore
cannot be discovered only after copying the first child. A future streaming
producer must state its affected validation unit: refusal of a later unit does
not undo previously accepted unrelated work or promise global preflight.

## 3. Claims, mappings and distinct admission responsibilities

The selected handler derives its write footprint from typed meaning. For these
handlers that is one `Leaf` claim per output; the supplied declaration must match
exactly. Omitting a destination, declaring another destination, adding a broader
shape or adding an extra destination refuses. In the model, ordered claim equality
is deliberate; normalizing declaration order would not change this obligation.

Validation checks same-root duplicate destinations and component-wise leaf or
exclusive-tree ancestry in both orders. Directory-ensure plus descendants is a
different compatible shape; neither tested leaf handler creates directories.
Each target has a root identity and a normalized relative route. The copy's source
is a separate coordinate with a source role; `source-A` is not a writable target.
Thus `source/a → target/z` is selection/routing data, not an implicit source-name
writer. Two different source routes mapping to one destination refuse.

The parameters do not grant arbitrary writes: only the checked request reaches
the finite handler, and that handler passes exactly its declared destination to
the runtime adapter. Runtime code is **trusted**, not sandboxed or cryptographically
confined by claims. Any future staging area, permission adjustment, recursive
replacement, metadata tree or native command must have its real affected region
declared or separately granted as private runtime work. An opaque command cannot
claim only its displayed output file while rewriting a whole workspace.

Keep three different questions separate:

1. **Desired admission:** which physical/generated logical candidates exist,
   with which origin and enumeration completeness? The completed generated-input
   study owns that seam. This dispatcher receives selected work, not a provider.
2. **Dispatch/ownership:** which known interpretation receives an admitted unit,
   and which destinations/dependencies does it expose? This is the tested seam.
3. **Satisfaction:** does current target evidence establish this selected goal?
   Binding a handler or finding no physical difference proves neither.

An existing `reports-A/summary.txt` is observed target state, **not another
producer**. A selected physical copy/removal at that destination is a competing
claim. Claims remain present while any competitor can arrive, including after
the pending request is acknowledged and after rebind. The probe reconstructs
reservations from its frozen plan and never releases them; a real driver may
release them only when the relevant competing-discovery domain has closed.
They are ownership state, not receipts proving past effects.

Root IDs must resolve under a caller-owned binding contract. Distinct spellings
do not prove that two runtime roots are physically disjoint or nonaliased. The
fixture uses three known separate directories; it does not implement a general
root-identity/alias resolver. Unrestricted mappings still need predeclared claims,
disjoint reserved regions or retained admission claims with explicit late-conflict
failure. Descriptors do not remove that memory/ordering tradeoff.

## 4. Owned pending work, pause and acknowledgment

The exercised flow is:

```text
raw descriptor OR typed program
  → decode known meaning → validate all parameters and claims → bind handler
  → issue owned pending {ticket, position, typed work, chosen body/recipe}
  → runtime observes/executes and closes resources
  → acknowledge matching ticket + reply kind
  → update accepted count/component state and expose next dependent unit
```

Repeated polling returns the same pending request. Dispatch compares the **whole
request** against that pending value, not merely its kind/ticket. An altered
destination or a forged early report refuses before runtime effects. Acknowledgment
checks ticket and expected copy/report reply kind; a failure reply with the wrong
kind cannot block another unit. Successful acknowledgment derives the contribution
from the selected work, not a caller-supplied arbitrary count. Candidate state is
validated before replacing the old state. Wrong, consumed and pre-retry tickets
cannot advance it. No consumed-ticket set is retained.

For two copies, the discriminating pause is:

| Boundary | Saved progress | Next eligible work |
| --- | --- | --- |
| Before effects | Accepted copies 0; ordinal 1; all three claims reserved. | First copy. |
| First copy acknowledged | Accepted copies 1; ordinal 1; second child still unresolved. | Second copy, not report. |
| Second copy visible but not acknowledged | Still accepted copies 1. | Same unresolved second copy; no report publication. |
| Both copies acknowledged | Accepted copies 2; ordinal 1. | Report recipe `A:2:1\n`. |
| Report acknowledged | Accepted copies 2; ordinal 2; terminal sequence. | No work; claims still retained. |

The composite is **scheduler-owned expansion**: neither source-leaf handler recurses
and no child has a second executor owner. Optional continuation saves this small
position, accepted aggregate, frozen program, next ordinal/ticket, pending data and
block flag. The probe retains the static program to compare exact supplied
parameters and reconstruct reservations; it contains no per-attempt write results
or completed-effect catalog. A full walking driver would instead reuse its existing
frames/remaining suffix; it should not add this second sequence owner.

On runtime error, retain the unresolved position/body and accepted prefix; retry
issues a fresh ticket for that same goal. In both leaf handlers, failure **after
visible output** leaves logical progress unadvanced. Retry reobserves current bytes
and can settle without rewriting. An unacknowledged request restored after visible
output also remains unresolved; decoding it is not acceptance. Ordinal advances
only when the report result is accepted, not when rendering or writing begins.

A ticket guards only this advancing state lineage. Forked or older snapshots can
repeat work; a trusted caller can lie in an external acknowledgment. No cross-process
exactly-once delivery, transaction between cursor and effects, locking, rollback,
recovery guarantee or effects history follows. Generic skip/coverage machinery is
not reimplemented: use the completed execution contract's abandoned-incomplete
rules, never reinterpret skip as generated satisfaction.

### Chosen bodies and recipe compatibility

The recipe retains version, label, accepted count and chosen ordinal. A pending
chosen body retains its bytes and the same interpretation stamp; the static
selected program also fixes those chosen bytes in this tiny model. Restore checks
pending work against the canonical work at the saved position. Changed body,
recipe version/count, component ordinal, label or supplied program refuses rather
than silently replacing future input. A new run with label B is allowed; resuming
label A as B is not.

For a real nondeterministic producer, move its chosen bytes into owned pending
state after production and validate their relation to the frozen producer/input
binding; do not rerun a clock/random/service-dependent recipe and call the new
answer the same request. Duplication of chosen bytes in this probe's static program
and pending value is a small compatibility discriminator, not a recommended storage
layout. If exact bytes cannot be reconstructed, structure/identity checks do not
prove their historical authenticity.

An immutable body reference is a later alternative: save store/binding identity,
content identity, length/format and required lifetime through settlement; missing
or incompatible retrieval refuses. No reference store or codec compatibility is
proved here. No open file, stream, closure, staging handle, permission lease or
started job is hidden in `Saved`. JSON reconstruction is optional scratch transport,
not the project's native codec or a process-continuation claim.

## 5. Actual probe checks and evidence bounds

The tests in `.test-agent/action-dispatch/src/lib.rs` establish:

| Test discriminator | Observed result |
| --- | --- |
| Raw versus typed construction | Same typed handlers, destinations, order and finish reservation; repeated poll returns the same request. |
| Unknown/malformed descriptor preflight | Unknown top/child kind or version, extra `shell`, escaping source route, unknown byte rule and nonstring label refuse before a runtime is constructed. |
| Declaration versus handler footprint | Missing/wrong/additional destination or broader shape refuses; late claimant still conflicts after acceptance and saved-state reconstruction. |
| Mappings/origins | Two source jobs mapping to one target, leaf/exclusive-tree ancestry, source-role confusion and incompatible generated producer version refuse. |
| Request/ack checks | Forged target, wrong ticket/kind, old retry ticket and duplicate accepted acknowledgment do not advance progress; forged target performs zero writes. |
| Composite pause | One accepted copy survives reconstruction; early finish is rejected; report uses both accepted children and advances ordinal only on acknowledgment. |
| After-visible-error retry | Both real handler meanings stay unresolved, then settle current model bytes with zero repeated writes and no saved effects log. |
| Visible but unacknowledged | Restore preserves unresolved report and ordinal 1; reassessment no-ops, then acknowledgment advances to ordinal 2. |
| Chosen body/recipe compatibility | Chosen `chosen-clock=42` and deterministic report survive reconstruction unchanged; mutated bytes/stamp/version/ordinal/label refuse. |
| Prior generated target, A → B → B | Previous bytes are replaced, parameter-changed desired bytes replace A, repeated B settles with no new write; no old-output producer is invented. |
| One real filesystem case | Copies `real-source`, writes `A:1:1\n` over previous report, injects error after closing visible output, reconstructs and retries with zero new writes; existing directory and Unix dangling symlink refuse without replacement. |

**Probe policy, not product defaults:** exact regular-file bytes; metadata attributes
unspecified; collisions, unsupported schemas and wrong kinds refuse. Acquisition
errors never become absence or satisfied. The real adapter uses explicit
`symlink_metadata` and bounded byte reads, checks real root/ancestor directories,
and directly overwrites a checked regular/absent file, closing it before return.
It has **no staging, atomic replacement, durability, permission preservation or
cleanup guarantee**. This anchors handler meaning and resource-closed retry only;
it is not the production sync installer or a generic physical policy adapter.

The single owned fixture has at most **8 workload entries and 512 bytes**, including
its `fixtures/` parent, below 256 entries/1 MiB. It removes only its exact owned
fixture on success; the final check found no remaining fixture entries. Build
output is isolated at `.test-agent/action-dispatch/target`, outside workload bounds.
Model routes are tiny UTF-8 strings and root-role labels; no native name encoding,
hostile-data/resource validator, runtime provider, crash test or native command is
claimed. Input JSON is already parsed before descriptor binding; the field/body
limits are not a hostile decoder allocation bound.

## 6. Remaining forks and next reuse point

The next reusable seam is **validated typed intent + visible claims/dependency +
owned request/ack**, attached to the existing caller-built driver. Reuse its pending
owner, accepted aggregate and component state; do not introduce a parallel dispatcher
cursor or edit core physical `Action`. The completed builder handoff can keep its
concrete executor `match`; a descriptor adapter belongs above it only when a real
external/stored job boundary needs one. Parent integration, not this independent
study, will compare against the completed walking demonstration.

For source-to-many work, keep source binding/input identity distinct from each
target's root, route, claims and settlement. A source read/body may be shared by
an invocation-local cache or immutable owned input, but each destination needs its
own satisfaction and acknowledgment. Decide whether aggregation counts sources or
target deliveries; the current accepted-copy count is not a universal multi-target
metric. Resolve root aliasing before treating two root IDs as independent writers.

For native consumers, add a caller-owned typed variant with explicit input binding,
working-tree/metadata write region, prerequisites/readiness and retry meaning.
A joined native operation may legitimately be one coarse unit; it must not claim
fine child pause boundaries or automatic observable satisfaction. If its effects
cannot be reassessed, expose deliberate retry/skip choice rather than manufacturing
idempotence. No shell string or global plugin registry is needed for that extension.

Still consumer-owned: byte/digest/always-install satisfaction and demanded
attributes; refusal versus declared collision winners/coalescing; mapping breadth
and reservation lifetime; same-tree output's input/exclusion domain; partial-result
finish policy; body storage/migration; handler unit granularity and runtime private
write grants. None blocks the finite typed seam proved here.
