# Outcome: preserve the composition; narrow the machinery

The early architecture was substantially right **as a composition**, not as a
reason to introduce every sketched abstraction. The independent returns support
immediate inspection, pure assessment, explicit selected work, one recursive owner,
postorder finish and owned continuation. The new walking specimen now demonstrates
that combination with real effects and supplied components.

- **Survived:** generic ordinary-directory work first; native ownership outside
  core; facts distinct from permission; state outside speculative callbacks;
  runtime distinct from saved future data; no effects history or rollback promise.
- **Narrowed:** typed application `Work` and direct dispatch precede descriptors;
  generated finish production precedes providers; caller progression precedes a
  shared universal walker. Packed names and Snapshot remain choices with costs,
  not blanket optimization verdicts.
- **Changed or made decisive:** desired satisfaction and destination claims need
  their own boundary; clean physical batches must retain finish work; effectful
  phases and acceptance own folding and mutable component state. Native cache
  adoption is a **membership transition**, not merely stat reuse. Existing targets
  should keep equal-subset/reset rather than import full source membership.
- **Still human policy:** new-creation default scope, reseed-before-default order,
  unavailable-capability behavior, and any deliberate change to transfer breadth,
  snapshot classification or clear authority. Native feasibility does not choose
  these. No production default changed during this flight.

The direct amended candidate is [statement1](statement1.gpt61sxh.md). This account
compares against [statement0](statement0.gpt6a.md) **at `013bec8a`**, not a
retroactively strengthened or weakened version. No unconditional early bet needs
to be declared wholly contradicted: the important amendments concern mechanism
necessity, scope and new authority constraints. Its existing hedges deserve credit.

## Reading and evidence discipline

The initial three architecture returns were independent of the parent stakes and
each other. Later studies used authorized completed prerequisites; syntheses were
explicitly allowed to integrate them. The execution-model author encountered
tracker return summaries **after writing/testing**, reports no other Wave 1 report
or parent stakes read/used, and disclosed that exception. Graph1 was a targeted
parent question after graph0, **not another blind initial study**. Other returns
declare their exclusions. Shared brief, code and earlier evidence also limit how
much agreement should count as independent confirmation. This is not a claim that
the whole flight was perfectly blinded or every result independently replicated.

Revision coordinates below bind the report/evidence used. Source-derived analysis,
ignored scratch models, delivered example tests and actual native fixtures have
different strength. Reported checks are trusted within their scopes, not rerun.
The current maintained architecture is an integration view, not additional proof;
the flight ledger supplies orchestration only and has older status rows.

## The nine named early bets

### 1. Existing observation/visitor machinery feeds a small stateful driver — supported

**Early wording:** statement0's component flow and first comparison row, not a
mandate to turn `PlanWalk` into the only driver.

Wave 0 [structure](structure0.gpt6am.md) `e4eeb968`,
[contracts](contracts0.gpt61sxh.md) `037b124a` and
[scenarios](scenarios0.gpt6am.md) `b046bbfb` independently locate the immediate
inspector as the shared seam. [Model](../execution/model0.gpt61sxh.md) `3113dfd2`
adds five scratch tests; [walk](../execution/walk0.gpt61sxh.md) through `b49cfc59`
supplies a committed specimen rather than scratch-only code, with real process gates.

**Amendment:** keep comparison traversal and current recursive sync intact. The
caller-built effect driver owns every edge it expands and consumes immediate
batches directly. A future sync adapter must expose closed nonrecursive units or
own an explicit continuation itself. Wrapping today's recursive `apply_plan` is
not child-sized stepping or stale-plan retry. A universal core walker is neither
needed nor demonstrated.

### 2. Component construction and portable parts stay separate — supported, bounded

The early statement explicitly left Rust generics for a walking experiment.
[Builder](../execution/builder0.gpt6am.md) `91d2f7e3` and delivered walk show a real
Bon builder, used supplied inspector/executor objects, codec-free reconstruction,
optional Snapshot, and a saved manifest ordinal that survives fresh processes.
These are stronger evidence than a descriptor selecting hidden defaults.

**Amendment:** save every behaviorally necessary component datum, not only its ID
and parameters. Bind validates data/configuration separately from filesystem
binding and active attempts. This proves a concrete program/manifest and two
replaceable I/O seams, **not arbitrary heterogeneous component serialization**.
Additional stateful components must expose/reconstruct their data or disallow the
affected pause. Core remains independent of codecs and executors.

### 3. Extensible descriptors plus built-in actions suffice — conditional; narrow first

Statement0 already prefers typed known parameters, separates executable code, and
exempts ordinary comparison from mandatory dispatch. It does **not** demand global
plugin discovery. The independent finding is therefore a smaller first design,
not a refutation of a registry it never required.

[Protocol](../actions/protocol0.gpt6am.md) `134e0c35` establishes why adding an
enum variant alone fails: no generated physical slot/facts, clean-plan loss and no
generated byte source. [Generated](../actions/generated0.gpt6am.md) `1b398a3f`
passes eight scratch tests; [dispatch](../actions/dispatch0.gpt61sxh.md) `7a325e0c`
passes eleven, comparing typed construction with a finite versioned adapter.
Walk delivers direct typed dispatch, not that generalized adapter.

**Amendment:** caller-typed goals, explicit desired content, target claims and
checked request/ack are primary. A finite `{kind, version, parameters}` adapter
decodes into that same checked path at a real external/stored boundary. It does
not grant hidden writes, settle satisfaction, discover children or own a second
cursor. Providers earn their cost only when virtual children join discovery; the
two-level generated-provider scratch proves that narrow possibility, not a
production all-input provider. General sufficiency for arbitrary handlers remains
unresolved; no such requirement needs to block the concrete compositions.

### 4. Postorder completion and small accumulators are useful — supported

The original assessment cursor (`6c893ca1`, twelve reported tests) demonstrates
pure postorder outputs. Walk demonstrates accepted child counts and an effectful
finish before parent closure, with the ordinal advancing only on accepted finish.

**Amendment:** make **before → assess → children → finish** and one-time
acceptance/folding explicit. Production, goal settlement, entity completion and
delivery differ. Effectful finish consumes an effect allowance; it cannot hide
in a free pop. Skip marks every active ancestor incomplete immediately. Small
counts suffice for these consumers, not every possible reducer. The
[modes study](../transfer/modes0.gpt6am.md) `053ecfe0` also shows that satisfaction
proof needs a sufficient aggregate—or a different result contract/enumeration—to
produce exact descendant counts. Proof of satisfaction does not manufacture them.

### 5. Inherited modes remove worthwhile assessment work — conditional on payoff

The semantic shortcut is supported by five counted fake-observer tests in modes.
Uniform population removes ten policy and ten one-sided classification calls in
its fixture; **source listings, entries, attributes and copies stay identical**.
Residual exceptions narrow per branch. Those are model counts, not production
syscalls or speedups. Source-only copying already omitted target interiors.

**Amendment:** carry explicit region/mode, residual rules, desired/removal authority
and reduction requirements. Separate NotAssessed, Preserved, CompletedByProof and
Incomplete. Full late Visitors keep their fact/override contract; compiling
overrideable late presets into terminal early exclusions is not transparent.
“Worthwhile” production payoff remains unmeasured. The actual early text already
says whole-tree copy normally enumerates and installs; that qualification survived.

### 6. Retained names/offsets beat repeated owned-name construction — conditional

[Names](../observation/names0.gpt61sxh.md) `887fb681` combines actual-core tracing
with a **separate reduced common-shape** comparison. Arena-only reduced allocation
events by 29.3% but **increased requested bytes by 6.4%**. Arena plus split/lazy
paths reduced events by 94.1% against the reduced owned case, not against an
equivalent optimized production core. Every working mode retained the same
72 statx and six getdents64 calls. Pinning the arena for one 200-byte child retained
31,744 bytes instead of promoting 200 bytes.

**Amendment:** first remove duplicate native handle/key name ownership and eager
success-only diagnostic paths without public lifetime changes. A later narrow
batch can own packed names and lend views, promoting survivors on release.
Existing `&Name`/contiguous `&Path` interfaces cannot magically expose split
coordinates. No custom parser/transmute is justified now. Statement0 already
identified ownership as the problem and disclaimed a dirent-to-PathBuf cast;
the study confirms that, while rejecting any stronger unconditional memory win.

### 7. Kopacetic fits useful cursor payloads — supported; specialization conditional

[Codec](../observation/codec0.gpt6am.md) `8b709ce0` reconstructs eleven paired
specimens exactly, including native bytes and effect-state data. Actual walk then
uses Snapshot in real process continuation while its library remains codec-free.
The checked same-shape prefinish specimen is 4,394 Snapshot bytes versus 730 for
a checked typed-rkyv envelope. Byte vectors are single Bytes scalars, not thousands
of reflected byte rows. Allocation observations are one-shot requests, not timings.

**Amendment:** keep optional Snapshot for the specimens; keep semantic Saved data
independent of transport. A stable high-frequency/large format can specialize if
representative size/allocation/save-frequency budgets justify it. Statement0
already called reconstruction owned and assumed neither speed nor minimum size:
the report does not overturn that hedge. Codec/layout costs must remain separate.

### 8. Native colocation can be the jw add default with useful copying — conditional

[Metadata](../native/metadata0.gpt6am.md) `014db6e3` first demonstrated topology,
including the **nonempty Git index after sparse-empty creation**.
[Colocation](../native/colocation0.gpt61sxh.md) `9b4fc6ec` subsequently passed ten
tiny native cases, including real reflinks, equal/different desired trees, both
archive backing forms, opt-out, root and clean-merge controls. Unchanged prefills
retained their inodes. Runtime: JJ `0.45.1-33d3a595…`, Git 2.55.0, Linux/btrfs.
This supports native feasibility and retained useful copying, **not checkout
performance, universal configurations, JW joint-mode support or a selected default**.

[Graph0](../native/graph0.gpt61sxh.md) `204653e6` adds one successful
existing-colocated equal-subset/reset case; it does not turn ten creation cases
into eleven reseed cases. [Integration](../native/integration0.gpt6am.md) `86efef77`
is source-only design, not another execution result.

**Amendment:** separate topology/materialization axes, thread receiving Git owner
through fallback/error cleanup, preserve native roots symmetrically, and adapt
verified JW-owned reseed guards/clear/payload/conformance. Keep ordinary native
materialization and the independent opt-outs. New-default scope and capability
failure behavior require explicit acceptance. Root may have unborn HEAD; native
multi-parent index need not equal first-parent HEAD. Do not “repair” those native
semantics with Git reset. Current JW selects one desired parent.

Native tree conformance is also not full POSIX-mode normalization: the study's
unchanged prefill retained `0600` where ordinary checkout used `0644`. Content,
executable state and links are the relevant native comparison; the route retains
useful donor attributes rather than promising an identical native checkout inode.

### 9. A registered workspace can be a useful source — supported, bounded

[Workspace source](../native/workspace-source0.gpt6am.md) `d6f19aeb` establishes
native registered-donor binding and reads existing JW `--from` support/tests.
This is **not newly delivered JW support**. Donor contents/revision may differ
from the archive; receiver links resolve directly to the physical repository.
The native probes did not execute JW or prove sparse/private-state interchangeability.

**Amendment:** bind selected donor, resolved repository owner, primary policy root,
link owner, frozen source tip and independent desired parent separately. Preserve
omitted-`--at` versus explicit-`--at @` snapshot/freezing behavior. Archive remains
the normal scenario, not the only possible donor. Arbitrary directories and
Git-only worktrees do not become registered JJ donors by analogy.

## Consequential amendments beyond the nine-row checklist

### Native membership: the important correction to reuse

Statement0 correctly separates identity, copying and graph advancement, but does
not spell out source-state membership authority. [Graph1](../native/graph1.gpt61sxh.md)
`730e53b0` now makes that omission consequential. Two tiny receivers start with an
ignored local matching source bytes/kind/mode/size/mtime, with unchanged ignore
rules. Full truthful source-state adoption makes it tracked; restore removes it
because desired D omits it. The no-adoption equal-subset/reset control preserves
its inode. **Both end at exact tracked D with clean Git HEAD/index/status.**

For retained local region R, the demonstrated exact-path deletion hazard is
`R ∩ (tracked(S) \ tracked(D))`. If remaining untracked is promised, overlap with
`tracked(S)` itself matters. Shape/ancestor overlap also needs ownership treatment;
the one-leaf test is not runtime proof of all shapes. Source/cache accuracy is
not permission. This is not a bad-source finding, a bug alleged in current reseed,
or a demand for recurring donor validation.

**Decision:** keep existing-target equal-subset/reset **without source-state
adoption** for the next landing. Fresh creation may retain its supported complete
source-prefill/state adapter: its supplied source-only files are operation-owned,
not preexisting locals promised retention. Never attach full S state to a partial
prefill or only the equal subset. A future existing-target adoption optimization
must decline/refuse incompatible retention or obtain explicit membership authority.

### Generated work: satisfaction and namespace authority are not dispatch details

Physical equality still means the core's stated stat/literal-link predicate.
Generated desired bytes/attributes have an explicit satisfaction rule; Unknown
does not mean equal. A changed label on a **new run** can change desired work;
changing the bound label on resume refuses. Nondeterministic production must
retain chosen bytes/frozen inputs or an immutable reference with sufficient lifetime.

Resolve physical/generated, two-to-one and leaf/ancestor claims before conflicting
effects. A previous generated target is actual target state, not another producer.
Reservations survive pending-work acknowledgment while competing discovery remains
possible. Unrestricted mappings may need retained claims or documented late conflict;
the simple finish case should not pay for a global target index. Same-tree output
needs an explicit input/exclusion domain. The delivered walk instead selects
disjoint reserved reports and exact bytes **for the specimen**, not as defaults.

Current `Facts::metadata()` remains full actual Metadata (`visitor.rs:300–317`),
equal-leaf `InstallLeaf` remains illegal (`437–467`), and paired lowering still
drops clean plans (`pair.rs:92–103`). These current spot-checks support a new
caller work path, not pretending current actions/providers already implement it.

### Work avoidance: source-first lifetimes, not a replacement transfer backend

[Facts](../observation/facts0.gpt6am.md) `5423a71f` establishes explicit demand
and private acquisition/cache ownership. Existing internal sync already reuses
source metadata/link text. Full metadata demanded by copying does not disappear
because d_type is known. Windows enumeration already caches attributes; Linux
call counts must not be exported as universal syscall savings.

[Kernels](../transfer/kernels0.gpt6am.md) `0b10555a` traces replacement twice and
models retaining two real precheck plans in 5,680 requested live heap bytes. The
combined 20→13 metadata-call prediction is **not a measured optimized executor**.
Prefer local directory permission/owning-lease handoff, then reuse the successful
coupled replacement precheck while preserving intact refusal. Ordinary copying
already uses held descriptors/FICLONE or std offload. Exact output-mtime readback
answers a necessary receiving-filesystem question; it is not duplicate source stat.

### Source-to-many: share input evidence, never target success

Statement0's modest later-composition bet survives.
[Multi-target](../transfer/multi-target0.gpt61sxh.md) `947f02b7` passes eight bounded
tests with real filesystem and shared-offset anchors. Its model/anchor shows
source listing acquisitions 4→2 and metadata acquisitions 7→4; facts-only sharing
still reads five bodies, optional one-leaf byte reuse reduces that to three.
Both retain five accepted deliveries and three destination installations. These
are application counts, **not production syscalls, device I/O or speedups**.

Use one capped ready source cohort; detach paused/failed/divergent targets and
reobserve later rather than pin old batches. Every target keeps its own policy,
claims, goal, pending ack, aggregate and finish. Retirement is not skip. Start
with known-input application orchestration; private source acquisition/target
assessment factoring comes later if needed. Today's public inspector cannot
accept injected shared facts. Independent opens are the small default: `try_clone`
shares read offsets, and per-target copy fallback can consume them.

## Main restructures and a small next landing order

There is no evidence for a prerequisite whole-library rewrite. The meaningful
restructures are **seams and ownership**, not new frameworks:

1. Keep immediate physical inspection central; add desired work beside it, with
   explicit claims/satisfaction and caller-owned before/child/finish progression.
2. Keep Saved future data separate from runtime and optional transport. Extract a
   production closed-unit sync seam only for a selected finer-pause use case.
3. Separate acquisition from target policy when demand/shared-source consumers
   justify it; first land private name/path and sync-local fact/lease reuse.
4. In JW separate topology from materialization and bind source/desired/old/new
   tips plus actual receiving ownership. Creation and existing-target cache routes
   remain intentionally different.

**Recommended next product sequence:**

1. Fix the focused evidence prerequisites in the paths about to be used: safe
   native fixture placement/delegation, consistent Cargo artifact lookup, and
   actual sibling dependency attribution. Preserve existing helpers where sound.
   Track the original missing-workspace identity bug separately; default changes
   are not its fix. No new large campaign is needed.
2. `diffdir-tree-native-create-compose`: repair owner-safe failure/fallback and
   capability diagnostics; after acceptance of independent axes, enable explicit
   joint mode with focused real-JW tests. Leave the unset default unchanged.
3. `diffdir-tree-native-reseed-owned`: bind verified JW-owned linked metadata,
   preserve both roots through guards/payload/explicit clear, keep no-adoption
   equal-subset/reset, and test retained membership plus native conformance.
   External or malformed ownership remains rejected.
4. `diffdir-tree-native-default-policy`: after the selected compatibility boundary
   works, land accepted add-only/shared-creation and capability behavior with
   help/config/output/tests. Integration recommends reseed first; creation-only
   remains a viable explicitly acknowledged human choice.

Private allocation/lease/precheck improvements can land independently, each with
its own tiny semantic and cost discriminator. A general effect adapter, sparse
facts API, generated provider or multi-target inspector should wait for its first
concrete production need, not block the native sequence.

## Human handoff and remaining work

The few decisions before that native product change are:

1. **Creation contract:** accept independent CoW/colocation axes, including changed
   cross-axis precedence; default only `add`, or all new creation including missing
   intermediate/final switch targets? Existing switch never converts topology.
2. **Reuse compatibility:** require owned-colocated reseed before the default
   (recommended), or accept a creation-only period with explicit `--no-colocate`
   for reseed workers?
3. **Support/failure scope:** which native builds/configurations are supported,
   and does unavailable selected/default colocation refuse before mutation
   (recommended) or downgrade with an explicit actual-topology diagnostic?
4. **Policy delta, if any:** recommended landing keeps selected ignored-root
   mirrors, empty/disabled/no-match selection, post-snapshot classification and
   existing explicit-clear authority. Broad refresh, standing vanished-root
   deletion or invocation-time untracked preservation require separate selection;
   none follows from this architecture or cache quality.

Optional continuation additionally needs a real pause use case and an explicit
uncertain-native-command boundary: replaying unacknowledged `jj new D` can allocate
another change. Generated collision/satisfaction policy and multi-target limits
belong with their selected consumers; they are not blockers for today's copy or
the native landing above.

[Operations](../evidence/operations0.gpt6am.md) remains source-only design. Fixture,
artifact/build-input and budget/residency implementations remain open. So does
`diffdir-tree-native-identity`, the original registered-missing-workspace
remove/prune discrepancy. The new native implementation stubs are not started
or approved defaults. Completed research does **not** close execution/actions/
observation/transfer/native umbrella work. Parent owns maintained-body/index
