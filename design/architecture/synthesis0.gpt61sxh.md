## Agreements carried into the baseline

1. **Shared immediate inspection, not one universal recursive walk.** Core,
   recursive sync and a caller-built assessor reuse observation/finalization.
   Each composition assigns exactly one owner per recursive edge.
2. **Facts and decisions are different.** Actual presence, unknown hints,
   unsupported observations and exclusion cannot collapse. Pure steering consumes
   supplied/frozen inputs; filesystem observation itself is read-only I/O.
3. **Logical progress has an ordered owner.** Speculative decisions are not
   notifications. Accepted child/finish dependencies, coverage and folding belong
   to the driver, while live effects belong to its executor.
4. **Observed differences do not define all future work.** Current divergent-only
   publication suits current actions. Generated or finish work in an equal physical
   directory needs a work/control projection that cannot silently discard it.
5. **Completion is scoped.** Assessment, target policy satisfaction and delivery
   are distinct. A reducer can produce bytes without installing or delivering
   them. Generated content does not become a physical source observation.
6. **Continuation is optional owned future state.** Runtime resources are rebound
   or settled; behaviorally relevant component state must be represented,
   reconstructible or outside allowed pauses. There is no effects history,
   rollback, crash transaction or exactly-once output promise.

## Tensions and choices made for research

| Integration point | Baseline choice and remaining question |
| --- | --- |
| Physical default versus operation intent | Keep the root's read-only stat/literal-link comparison unchanged. Mirror deletion and update retention are explicitly chosen existing sync operations. No architecture sentence makes comparison mutate, or selects a new JW target-only default. |
| Producer/installer versus desired-input provider | Both are valid narrow compositions. Require explicit generated provenance, destination and satisfaction semantics when reconciled; do not select an all-input-provider framework. A completion-produced logical output need not be installed at all. |
| Generated equality versus action parameters | Output-affecting parameters enter desired/satisfaction semantics rather than bypassing an equal physical slot. The rule is required; hashes, rewriting, receipts and byte-stream/recipe representation remain open. |
| Existing seals versus new work | Preserve silent clean comparison. Require the extended driver to expose selected work/control obligations and seal dependent descendants even with an empty baseline diff. Whether this is a separate projection or broader rich surface is unresolved. |
| Assessment step versus effect step | Choose one attempted immediate-directory assessment as the assessment budget unit. Initially allow effects to pause only between joined units; an opaque recursive apply remains valid but unbounded. Child-sized pause state and fold ownership need design. This normal continuation state is not a recovery transaction. |
| Reducer completion versus effectful finish | Pure folding may produce a value or select finish work. A unit with effectful obligations cannot claim closure until they settle or are explicitly skipped incomplete. Delivery has its own outcome and no exactly-once receipt. |
| Component construction versus serialization | Establish semantic assembly seams without selecting exact Rust generics or global registration. Each stateful component owes a pause-state explanation; a codec cannot serialize closures or hidden live resources by assertion. |
| Whole-subtree knowledge versus policy coverage | Require predicate/domain and named savings. Proven satisfaction differs from preservation/skip. A tracked-tree identity does not cover ignored data or prove the receiver matches. No automatic subtree shortcut is selected. |
| Native preference versus evidence | Incorporate demonstrated native creation from both archive forms, and the nonempty sparse-empty Git index. Keep combined prefill/adoption research separate and default-on colocation conditional. Today's mode rejection is not a feasibility verdict. |

General output collision policy, all-input providers, action registration, finer
effect pauses, archive schema and broad JW copy defaults remain open. Requiring
conflicts to be settled before conflicting effects is not choosing how they settle.
No extra disposition layer or native metadata transplant protocol is introduced.

The strongest immediate interface discriminators are effect-phase/fold ownership
and selected generated work in an otherwise equal physical directory. Neither
requires settling a global framework first.

## Scoped follow-on commissions

These questions derive from the independent conclusions above, not a comparison
with withheld material. The [maintained statement's discriminator table](/doc/architecture/README.md#delivered-seams-and-next-interface-discriminators)
is the short entrypoint; the following explains what each answer must distinguish.

### `diffdir-tree-execution-model`

Can a caller assemble one driver that represents assessment, prerequisite work,
child position and effectful finish without duplicating recursive ownership?
State the smallest pending phase and aggregate protocol for one created directory,
two installs and a finish obligation. Compare a whole recursive unit with a pause
after one visible install and before finish. For retry/skip, identify actual
remaining work, which local result is retained/recomputed and when ancestors fold
once. A saved position is not evidence that earlier effects succeeded, and need
not retain their history. The answer selects pause granularity and state ownership,
not a journal, universal scheduler or exact constructor generic list.

### `diffdir-tree-actions-protocol`

What is the smallest input/work protocol that carries generated provenance,
parameters, target satisfaction and child/finish dependencies through ordered
publication? Trace equal physical roots with legitimate selected generated work,
then a physical/generated name conflict and two logical inputs mapped to one target.
Compare a narrow producer/installer with desired-input admission. Preserve actual
physical facts and the ordinary diff projection. Expose collision-policy choices
and required target ownership without deciding them through enumeration order.
Use one changed output parameter to discriminate satisfaction semantics; do not
require extensible global registration merely to dispatch a second handler.

### `diffdir-tree-observe-facts`

Which facts are demanded by each decision and separately by execution? Build a
table for early preservation, physical comparison, literal links, removal, copy
metadata and generated satisfaction, with Known/Unknown enumeration hints. Name
the I/O owner and transient/retained lifetime; hint access must not acquire facts
implicitly. Include one scoped whole-subtree assertion and identify exactly which
enumeration/assessment/effects remain. This selects a demand/acquisition contract,
not fake `Metadata`, unsafe name storage or a universal provider framework.

### `diffdir-tree-transfer-policy`

Which source-present overwrites, target-only removals and type replacements are
authorized for each selected operation, and what is preserved? Separate generic
mirror/update/seed choices from JW's unresolved data breadth, ignoredness and
classification around native snapshot/materialization. A new/existing receiver
matrix must protect receiving root `.jj` and `.git` even if absent at source;
retained descendants constrain container replacement. Broad donor copying does
not itself select mirrored deletion. Return the human policy forks, not new
defaults or assumed native prefill feasibility.
