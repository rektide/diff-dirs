## Inspect owns the live boundary

[`inspect_declared_group`](/tree/inspect/src/declared.rs) accepts ordered Exact
declarations or TargetCensus. The public selector lends pure route/entry demand,
checks and choices; inspect owns actual observations, complete immediate semantic
validation, outstanding execution acquisition and `PreparedDirectory` construction.
There is no inspect-to-sync dependency or public selection-plus-metadata shortcut.

- Exact S coordinates are looked up directly, including when both trees lack the
  leaf. Missing source, wrong kind and an incorrect executable expectation fail
  that obligation. Unix executable means any `0o111` bit; other platforms refuse
  the requirement. Symlinks cannot carry it.
- O-only and census entries carry NotRequested source. They do not admit a source
  route, look up an unrelated source child, enumerate source, or receive a peer's
  source facts. Asking for such source facts is an integration refusal.
- An admitted real target route's genuine missing prefix establishes declared
  descendant absence. A leaf, symlink, ENOTDIR or other I/O failure does not.
  Census requires a real present directory, never an invented empty census.
- Route guards see actual bound-root-to-containing-route directories on their
  identified side. Entry guards see only their own requested masks. Expectation
  and selected execution demand use the same retained cells.
- A direct lookup retains the complete actual metadata with AcquiredMetadata
  origin, rather than relabeling it RootMetadata. Current-epoch directory facts
  can seed route reuse; retained cross-call source facts cannot certify a route.

The existing SourceSession generation, capacity charge and finite successful-cell
retention remain the owner. Sparse positives never set OriginalListing or imply
absence of unqueried names. A later physical union still enumerates completely,
preserving its original hints rather than strengthening early policy input from
lookup history. Failures/negative lookups are call-local; successful acquired
metadata and link text are reusable. Declared diagnostics attribute entry metadata,
link acquisition and fact reuse separately from route checks and actual effects.

## Manifest authority and the effect gate

[`PreparedLeafList` and `OwnedLeafSet`](/transfer/sync/src/listed/manifest.rs) own
immutable Arc-backed component indexes. Constructors are filesystem-free and
reject empty/absolute/escaping/NUL paths, duplicate aliases and within-set
leaf/ancestor conflicts. Desired specs retain exact expectations; the compatibility
constructor uses SupportedLeaf. Clones and receivers reuse the existing indexes.

ManifestId version 1 is a platform-tagged BLAKE3 digest of domain-separated,
length-prefixed ordered native components and desired expectations. Desired and
owned domains differ. Unix bytes and Windows UTF-16 units have explicit encodings;
other platforms refuse preparation. This is declared-data identity, not a donor
content digest, native tree ID or ownership certificate.

[`EffectBinding`](/transfer/sync/src/binding.rs) owns validated disjoint physical
roots and CopyPolicy independently of an ordinary Policy or Comparator.
`Applier::binding()` lends that same portion. The listed runner performs no ordinary
root admission callbacks and invokes no comparator: its comparison is NotAssessed.

The private [`bind_listed_batch`](/transfer/sync/src/listed/selection.rs) gate checks
actual S/O identities, source generation, roots, final coordinate, private placement,
exact leaf/node references and copied expectations, weakest intent-specific grants,
child/enclosing slice relations and complete immediate declaration coverage. A
census binds every actual child to O. Execution readiness includes fallible required
field extraction, before any effect scope for that batch. Generic shape/action
legality remains exclusively inspect's common validator.

Corruption tests construct genuinely live, generically valid preparations with an
omitted slot, wrong LeafId, changed expectation, overbroad CreateAbsent grant,
wrong-coordinate OwnedLeaf, overbroad CoupledOwned node or wrong interior slice.
Actual binding refuses all with zero effects. NoExecutionDemand preparation can
pass read-only binding but fails the effectful readiness gate without fallback I/O.

## One recursive owner and truthful coverage

[`reconcile_listed`](/transfer/sync/src/listed.rs) owns the whole coarse call.
Immediate selections/binding precede their effects. Promoted child/finish jobs group
compatible desired coordinates **before** the next inspection, regardless of absent,
retained or privately staged targets. No entire receiver runs before its peer.
Immediate preparations are released before grouped desired-child recursion; census
recursion promotes its child continuations rather than pinning ancestor batches.
Listed scheduling is serial; it does not add another pool or promise leaf-sized
pause points.

- CreateAbsent uses S only, even when O is supplied. It never overwrites or removes.
- RenewOwned replaces an occupied supported leaf only at an exact O leaf. An old
  exact O leaf now holding a directory refuses, including when S wants a route.
- A desired leaf collapsing an O structural directory owns the subordinate work.
  Full read-only TargetCensus preflight visits **every actual directory** and vetoes
  unknown leaves and unknown empty directories before that transition's staging,
  chmod or subordinate O deletion. The effectful pass repeats census under the
  same scope; there is no flat O-minus-S deletion pass.
- Leaf-to-directory expansion prepares S children only. Unlisted donor children
  never enter staging. Old leaves survive failed private preparation.
- O-only supported leaves remove or ConfirmAbsent. O-only structural directories
  remain after their children retire; no automatic empty-directory prune occurs.
  An absent structural marker binds and retires its exact obsolete subtree once,
  with retained zero, even though it has ApplicationNeed::None.

Coverage is separate from actual effects: desired, installed, owned_obsolete,
owned_retired and complete. Same-coordinate desired/owned leaves are renewal, not
obsolete retirement. Missing-prefix and coupled owners suppress redispatch of the
old subtree. Private desired counts/progress stay provisional until publication.
Already-visible removal and confirmed absence credits survive later failure;
there is no post-failure census. A cleanup/permission failure cannot complete,
even after every desired leaf rename succeeded. Outcomes preserve input binding
order, independent lane results, actual progress and original/secondary causes.

### Created-container scope correction

After preserving the first verified runner, review found that newly created routing
containers needed their actual post-umask scope **before child inspection**, not a
new lease created after it. Jobs now carry that one DirectoryScope and donor finish
obligation through inspection, children, arena cleanup and postorder finish. Creation
is credited immediately after mkdir; setup failure still finishes the owned container.
Failed private scopes discard only private progress, never visible siblings.

An isolated `umask 0777` child process exercises absent-root, retained-root and
staged-expansion receivers together. A deep guard failure returns exactly 3/2/0
visible directory creations and 6/4/0 permission calls; the old staged leaf survives.
A subsequent fresh coarse call reusing S/O indexes installs all three targets with
the donor modes. This also passes with real required reflinks.

`seed_leaves` is now a small CreateAbsent wrapper with a Check guard adapter. It
keeps actual full source metadata/literal-link checks and once-per-call routing
checks, including empty-list root checks. Its documented boundary deliberately
changes: a later sibling failure admits **no leaf prefix within that immediate
batch**; earlier completed batches remain. Failure diagnostics identify the actual
source/target coordinate rather than preserving the old seed-loop operation labels.

## Native integration API and remaining ownership

The public Rustdoc example at [`reconcile_listed`](/transfer/sync/src/listed.rs) is
compiled. The native integration shape is:

```rust,ignore
let desired = PreparedLeafList::from_specs(native_desired_specs)?;
let owned = OwnedLeafSet::new(native_owned_paths)?;
let binding = EffectBinding::new(source_root, receiver_root, CopyPolicy::ReflinkRequired)?;
let source = SourceSession::new(binding.source()); // canonical bound path/generation
let id = "receiver".into();
let report = reconcile_listed(&source, &desired, &[ListedTarget {
    id: &id, binding: &binding, owned: &owned,
    intent: ListedIntent::RenewOwned, guard: &native_guard,
}])?;
let lane = report.outcomes.into_iter().next().unwrap();
let effects = lane.outcome?; // outer Ok alone does not mean this lane succeeded
assert!(lane.coverage.complete);
// Only now enter the native owner's separate adoption/conformance protocol.
```

Prepare S once and O once per distinct native ownership set; lend them to multiple
ListedTargets. Reuse an existing SourceSession only for the same stable physical
source phase. A native guard checks actual device/admin/routes/attributes through
ListedCandidate and explicitly requested SideDemands; it cannot drop work or grant
replacement. For fail-fast consumer behavior, submit one receiver per coarse call;
a multi-lane provider call deliberately continues healthy independent peers.
