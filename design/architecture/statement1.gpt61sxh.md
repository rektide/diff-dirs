# Tree reconciliation

Tree reconciliation composes **physical inspection, pure assessment, selected
work, ordered progression and completion**. Core owns physical facts and read-only
comparison; sync owns filesystem effects; callers own desired outcomes, policy,
generated content and native repository lifecycles. Ordinary directory work needs
neither a codec, a handler registry nor a JJ/Git adapter.

This is a proposed amended statement, not a replacement for the governing
[core](/README.md) and [sync](/sync/README.md) contracts. The preserved
[early statement](statement0.gpt6a.md) and [comparison](comparison0.gpt61sxh.md)
record what survived, narrowed and changed.

## Composition and authority

```text
bindings + frozen intent → immediate physical inspection → pure selection
                                  ↓                           ↓
                         immutable evidence          validated desired work
                                                              ↓
                    one ordered owner: before → assess → children → finish
                                              ↕
                                  closed runtime effect units
                                              ↓
                                scoped completion / separate delivery
```

- **Bind separately:** logical identity, physical source, actual target and private
  preparation coordinates. A missing source root is an error, not deletion authority.
- **Observe honestly:** actual presence, unknown hints, unsupported kind and
  exclusion differ. The observer performs explicit read-only I/O; pure decisions
  consume supplied/frozen inputs and may repeat or run speculatively.
- **Select without rewriting facts:** physical difference, desired satisfaction,
  selected work and coverage are separate. Core retains its size/mtime/type and
  literal-link predicate; directories are structural, not recursive fingerprints.
- **Validate before affected effects/child admission:** actual routing, desired
  shape, preservation, destination claims and coupled replacements must agree.
  A retained descendant can block directory-to-leaf replacement intact.
- **Own each recursive edge once:** current paired comparison plus recursive sync
  remains valid. A caller driver expanding all children must instead use
  nonrecursive effects; it cannot also delegate those edges to recursive apply.

The shared seam is immediate inspection, **not a mandatory universal core walker**.
Read-only comparison may continue silently across clean batches. A work driver
must retain selected/control/finish obligations even when physical diff is empty.

## Selected work and generated content

Start with caller-typed `Work`, explicit parameters and ordinary dispatch. At an
actual stored/external boundary, a finite versioned descriptor may decode into the
same checked work path. It does not serialize code or confer undeclared writes.

A generated file supplies desired origin, target, bytes or reproducible inputs,
requested attributes and a satisfaction rule. It never fabricates source Metadata
or force-installs an equal physical slot. Unknown satisfaction remains unknown.
Output-affecting parameters are frozen for a continuation; incompatible restore
refuses. Nondeterministic production retains its chosen body or sufficient immutable
input/reference, not a recipe that silently chooses a different answer on retry.

A postorder producer/installer is enough for a report. A desired provider is an
optional child-discovery mechanism for virtual directories, with its own origin
and enumeration-completeness scope. Neither provider completeness nor unfinished
production grants removal authority over unlisted targets.

Resolve competing physical/generated, two-to-one and leaf/ancestor destinations
before their conflicting effects. Reservations remain while competing discovery
can occur. Wider mappings need predeclared claims, disjoint owned regions or an
explicit late-conflict contract. Same-tree output needs a declared input/exclusion
domain; separate reserved reports are one simple composition, not a library default.

## Progression, saved parts and failure

An ordered driver owns phases, pending goal, unclosed child suffix, accepted local
and child aggregates, finish, coverage and necessary component data. Container
work gates children; effectful finish gates closure. Checked acceptance removes
the child edge and folds once **within the advancing lineage**. A small accumulator
is sufficient when the consumer's result permits it.

Owned requests leave the driver before runtime preparation. The executor joins
work, closes staging/permission scopes and returns an acknowledgment. One attempted
immediate-directory assessment and one closed effect attempt are separate budget
classes, including failed attempts and effect satisfaction no-ops. Neither count
bounds entries, file bytes, memory, syscalls or elapsed time. Opaque recursive/native
operations remain legitimate coarse units, not falsely small steps.

At supported pause, Saved owns future data; Running rebinds implementations and
resources. Every stateful component must expose/reconstruct behaviorally necessary
state or prohibit that pause. Data/codec compatibility validation, filesystem
binding and current execution checks are separate. No open handle, borrowed
dirent, live lease or old plan becomes portable execution authority.

Failure leaves possible effects. Retry reobserves what the unresolved goal needs;
it does not replay stale actions or assume an error did nothing. A general
directory-batched Visitor adapter may require a charged full-batch refresh, without
recounting accepted results. Skip abandons its declared scope, immediately marks
ancestors incomplete and undoes nothing. Partial finish requires explicit program
permission. Completion is not a delivery receipt. Old/forked state can repeat work;
there is no effects ledger, rollback, crash-recovery or exactly-once guarantee.

## Work and representation costs

Specialize child context only under a sufficient region contract: preserve,
populate-empty, supplied leaves, proven satisfaction or explicit removal authority.
Carry residual exceptions. General assessment can disappear while required source
enumeration, copy attributes/bytes, deletion and finish remain. Satisfaction proof
needs sufficient reduction evidence to supply an exact aggregate. Preserved,
proof-completed and skipped-incomplete outcomes are different.

Keep existing full-fact Visitors compatible. A sparse path must expose explicit
availability and acquisition, not secretly fetch or fabricate partial Metadata.
Reuse current observations through their last immediate consumer; reacquire at
declared resume/authorization boundaries. First optimize duplicate private name
ownership, lazy diagnostic paths and local fact/lease/precheck handoff.

Borrow native names from owned/frozen backing; promote surviving coordinates when
releasing the batch. Packing is not automatically a byte-volume win, and requires
an honest public view/coordinate surface. No new parser or owning-path transmute
is selected. Optional Snapshot fits the specimens; specialization remains a
consumer-budget choice. Codec overhead, layout savings and production speed are
different claims.

For source-to-many, share a capped immutable current source batch, optionally one
bounded body. Keep every target's policy, claims, satisfaction, pending ack,
aggregate and finish independent. Detach laggards and reobserve rather than pinning
old batches or building a permanent catalog. Start with explicit known inputs;
shared directory acquisition needs a later real observer/assessment seam. Shared
source evidence never acknowledges a destination or removes required installations.

## Native archive and receiving workspace

The normal JW donor is the JJ archive. A registered donor remains a separately
bound checkout of its resolved repository, not the owner of that repository or
its policy defaults. Bind source tip S, desired parent D, existing post-snapshot
tip T and newly allocated receiver tip N separately. Copying bytes does not select
a parent; native revision advancement is explicit work.

Native creation supplies new identity; existing transitions preserve receiving
root/registration/repository and Git administration. JW symmetrically reserves
root `.jj` and `.git` against generic copying/removal, even when absent at source.
Shared Git common storage, private worktree administration, receiver `checkout`
and private `tree_state` are distinct owners/state. Native commands may legitimately
change operation binding, HEAD/index and revision without changing workspace identity.

Creation may use a supported complete source-prefill/private-state adapter followed
by native convergence. Existing receivers should keep **equal-S/D-subset prefill
plus sparse reset, without donor-state adoption**. Full truthful source state
imports tracked membership: a retained local in `tracked(S) \ tracked(D)` can be
absorbed then removed by restore. Good source and exact final D do not authorize
that transition or prove local preservation. Decline that optimization rather than
introduce recurring donor validation. Native readiness waits for complete tracked
and selected auxiliary/link obligations; a paused native phase is not ready.

Native CoW/colocation composition is feasible on the tested runtime, including
retained useful prefills. It is **not delivered joint-mode JW support, colocated
reseed or performance evidence**. Separate topology/materialization choices,
owner-safe fallback, verified owned-target reseed and capability handling precede
an accepted default. The preferred default-on colocation still needs human scope,
compatibility-order and failure-policy selection. No broad transfer, snapshot or
clear-policy change follows. Uncertain unacknowledged native mutation needs a
native-specific disposition, not automatic replay of `new D`.

## Delivery boundary and next landing

Current core/sync keep their specified inspection, comparison, staged recursive
effects and fresh public-plan validation. The original cursor remains assessment
only. **`examples/walk` is the delivered narrow new composition:** supplied Bon
components, real byte-copy/generated finishes, saved ordinal, owned requests/acks,
two attempt limits, native-byte state and optional Snapshot through four fresh
processes; eleven all-feature/nine codec-free tests are reported. Its exact-byte,
retained-extra, writable Unix and reserved-report semantics do not supply production
CoW, permissions/metadata, deletion, replacements, arbitrary providers or JW effects.

Next land focused evidence prerequisites and owner-safe explicit native composition;
adapt verified JW-owned colocated reseed on the no-adoption route; then land the
selected default/help/config/test contract. Production generic effect continuation
and sparse/shared inspection need separate implementation commissions, not as
prerequisites for that native sequence. Research completion does not close the
implementation umbrellas or the separately scoped missing-workspace identity bug.
