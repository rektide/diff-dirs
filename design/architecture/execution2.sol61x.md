## Stable consumer surface

The executable owners are now:

```rust,ignore
Applier<P, M = StatKey>
SyncTarget<P, M = StatKey>
SyncRuntime<P, M = StatKey>
SyncCursor<P::Context>
```

- `Applier::new_policy(source, target, copy_policy, policy, comparator)` binds
  ordinary contextual execution. `new_replacing_policy` explicitly authorizes a
  leaf-root transition. `run`, `run_in_pool`, `initialize`, `replace_root` and
  `preview` use the selected contextual interpretation.
- `SyncRuntime::new(Vec<SyncTarget<P, M>>)` owns the small executable P/M values;
  usual loans can use reference policies/comparators through their forwarding
  traits. Descriptors, policy/schema/comparator IDs and initial contexts remain
  independently frozen in `TargetBinding<C>`.
- `SyncCursor::new`, `from_parts`, `bind`, `next_group`, `refresh`, `apply` and
  `drive` now work with actual C, not merely generic saved DTOs. The existing
  comparison frontier still owns paired recursion and reduction; no second driver
  or unit-context opaque fallback was introduced.
- `SyncCursor::bind_with_source` accepts the real caller-owned
  `Arc<SourceSession>`/`ObservationResources` lifetime; `source_session` exposes
  that same live handle. Default binding creates one when the caller supplies none.
  `walk_in_pool_with_source` closes the borrowed-pool source-owner seam too.
- Full convenience constructors and `.scope/.absence/.visitor`, checks, audit and
  public full-plan refresh remain available through
  `FullPolicy<C,S,A,V> = FullVisitor<Steering<C,S,A,V>>`. Explicit old four-parameter
  Applier/SyncRuntime annotations must change to this owned adapter. Ordering

The default/full APIs infer their adapter type as before. The runtime itself never

## Preparation and continuation

[SyncCursor](/transfer/sync/src/coordinated/mod.rs) initially calls the existing
`next_group_prepared` with `PhysicalExecutionDemand`, retaining
`PreparedDirectory<C>` directly. The group, barrier and live preparation share one
selection Arc. On restoration/rebind, refresh:

1. Validates runtime descriptors, CopyPolicy, saved input contexts and every pending
   selected interior context before binding-route I/O.
2. Admits physical routes through one fresh epoch and inspects **all** pending lanes
   under their exact saved `input_context`, using `AlreadyAdmitted` and the same
   source/resources owner. Accepted lanes/ancestors are not refreshed or re-admitted.
3. Completes execution demand and pure required-input extraction for every refreshed
   lane, compares entire selections including context/grants, then retains the
   published Arc on each fresh preparation. A failed peer prevents the selected
   healthy lane's first effect; valid peers remain pending for a later request.

An `apply` request shares its epoch across internal refresh and application.
Standalone `refresh` discards routes on return; later application admits routes
again without replaying policy admission. Parts contain neither epochs, source
sessions, resources nor metadata. A `run` retains one actual source owner across
paired/opaque work and one effect epoch through its applications; the comparison
walker continues to own its separate joined read-only inspection epochs.

## Kernel, contexts and lifetime boundaries

The [kernel](/transfer/sync/src/kernel.rs) contains no P/M callbacks and does not
enumerate user trees. It owns leaf preparation/publication, sparse leaf removal,
container creation/empty removal, one containing-directory scope and private-tree
cleanup. Its recursive cleanup is exclusively for privately owned staging.

The [opaque runner](/transfer/sync/src/opaque.rs) owns `EffectCall`, independent
`LaneCall`, logical/physical `BatchPlace` and explicit `RecursionOwner`:

- Comparison-owned physical paired interiors are skipped by application. An opaque
  source-only/target-only/replacement call owns its entire selected interior,
  including any later paired shapes. `InteriorRole` decides this, not metadata or
  the appearance of a newly created directory.
- Exact selected contexts flow through copying, conditional ancestry, inherited
  target-only removal, replacement preparation, read-only removability, its second
  effectful pass, preview and structural-root dispatch. Policy/comparator paths
  remain final logical coordinates while private output paths stay physical.
- Leaf-local work borrows the immediate selection/facts. Only small contextual
  child/finish jobs survive before recursive inspection: paths, selected interiors,
  donor permissions and necessary publication/removal state. Collapse keeps its
  prepared descriptors, not the source fact slab. The immediate preparation is
  explicitly dropped before those child jobs run. A weak-Arc discriminator proves
  the live preparation no longer pins the parent arena; the group/barrier's
  intentional semantic references remain.
- Immediate leaf work joins before promoted interiors; directory modes finish
  postorder. Results merge by immediate native-name slot, not completion order.
  This remains nontransactional and is not a serial-mutation-prefix promise.
- One containing scope owns the lazy lease through all children **and arena
  cleanup**. An arena never captures a second lease's temporarily relaxed mode.
  Created directories are owned immediately after mkdir, before fallible setup;
  actual post-umask metadata is observed and donor modes finish even on failure.
- Conditional frames remain depth-sized and lane-local. They do no mkdir/chmod
  until selected ordinary work—including an explicit empty directory—needs the
  chain. Each actual creation is counted once during postorder unwinding.
- Private trees accumulate provisional progress until outer publication. Discard
  clears only that private accumulator. Visible siblings, real old-node removals,
  and containing-parent lease work survive later failure. Cleanup/restoration errors
  follow an existing primary cause; they become primary only when alone.

`BoundDestination` is private and checks its actual scope, selected grant/expected
shape and whether its coupled transition cleared the old node. Publication freshly
checks no-follow destination placement: AbsentOnly cannot overwrite a collision.
Directory collapse still preflights the entire selected removal subtree intact
before staging, permission relaxation or subordinate removal. The bounded two-pass
protocol uses the exact RemoveForReplacement context in both passes.

## Sparse facts and routes

`PhysicalExecutionDemand` requests source file attributes, source literal link text
(plus Windows-required subtype metadata), source directory donor attributes and
Windows-required target-link subtype metadata. Unix unlink consumes target kind
alone. Keep/preserve and removable/retained containers acquire no attributes merely
for their action. Containing write-lease acquisition remains separate and lazy.

`require_execution_inputs` checks the **whole immediate batch** before its effects,
including fallible source `modified()` extraction. A sparse preparation lacking
inputs refuses; the kernel has no fallback stat/readlink or synthetic full-fact
projection. The later-input-failure test uses deliberately injected loss of a
still-unacquired source link after selection, so it distinguishes both listing
backends without mistaking already-cached kind metadata for a new acquisition.
That test-only fault injection is not permission for production policies to do I/O.

[InspectionEpoch](/tree/inspect/src/epoch.rs) now has real cached positive/negative
directory outcomes, complete no-follow absolute ancestry admission, per-key cells
and short index locks. It rejects symlinks even before `..`. Namespace changes
invalidate endpoints/subtrees and parent attributes; chmod invalidates directory
attributes while existing leases retain their original modes. Parent-normalized
keys and invalidation agree even for compatibility input paths containing `..`.

Inspect can privately reuse directory metadata it actually acquired in the same
epoch after admitting its ancestors; no public metadata-certificate constructor
exists. Genuine missing-prefix Io/NotFound remains distinguishable from
NotDirectory/symlink/permission refusal. Target-only recursion requests no source
route. No cross-call route reuse, syscall speedup or charged source-cache claim is
made.
