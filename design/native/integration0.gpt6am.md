# Recommendation

**Compose the existing creation mechanisms first; adapt colocated reseed on its
existing no-adoption route; then select a shared new-workspace default.** Keep
generic transfer and optional continuation as independently landable work. A
builder/cursor replacement is not a prerequisite for this colocation fix.

My recommended product outcome is independent CoW/colocation axes, default-on
colocation for add **and missing-switch creation**, with `--no-colocate` and
`workspace.colocate=false` retaining JJ-only creation. Enable that default after
JW-owned colocated receivers can reseed. This avoids making the default workspace
ineligible for the normal reuse workflow. Human selection is still required;
this document changes no contract or default.

## Four consequential choices

1. **Scope:** shared new-workspace policy is recommended. It covers add and every
   missing intermediate/final switch name, never conversion when switching to an
   existing workspace. Add-only is viable but requires an explicit command-level
   default parameter; editing today's shared resolver is not add-only.
2. **Order:** explicit joint creation → colocated reseed → default is recommended.
   Creation-only default is a smaller alternative if the human accepts that reseed
   workers must temporarily use `--no-colocate`; help and examples must say so.
3. **Unavailable native capability:** recommend actionable preflight refusal for
   selected/default colocation, with the opt-out working on older JJ/non-Git
   backends. Automatic downgrade is a different product choice: it would need an
   explicit warning of actual topology. CoW fallback alone must never downgrade
   selected colocation. This choice matters to existing minimum-JJ compatibility.
4. **Transfer breadth:** recommend retaining the current selected ignored-root
   contract. Broad residual refresh or standing removal of vanished selected roots
   can be selected later as a separate policy/version transition. Neither empty
   lists nor disabled selection may become “copy the whole source.” No new flag
   family is needed for the recommended landing.

Keep current **post-snapshot classification**. Invocation-time untracked
preservation is a separate requested contract, not part of these four changes.

## Existing mechanisms versus proposed extensions

Inspected JW source/help/tests are unchanged from Git HEAD
`3b99f1d70a64c1251ccae9f4ca1942751671fe8a`; scoped `git diff --stat HEAD` for
`src tests docs README.md CONTRIBUTING.md` was empty. Evidence is attributed,
not rerun: native studies use JJ `0.45.1-33d3a595429b7e3b54a8ea769560247913bc8a1b`,
Git 2.55.0, with real reflinks on Linux/btrfs for colocation/graph cases. Their
inspected upstream source is sometimes newer. No all-version/platform, sparse,
conflict, monitor, filter or submodule guarantee follows.

No generic core should learn JJ revision, Git ownership, ignoredness or prepare
commands. JW supplies terminal symmetric reservations and typed native work;
sync owns filesystem effects. Existing listed-prefill and early-preservation
seams already avoid unrelated discovery. Whole-target emptiness is false after
native creation because `.jj`/`.git` exist; assert only the payload region's
construction conditions. Native tracked equality says nothing about auxiliary
data, generated output, local retention or reflink sharing.

## Bind actual source and target intent

Use a small command-owned binding, retaining the existing coordinates:

- `A`: verified physical primary/archive; `R`: shared JJ repository; `G`: Git
  common store. A named workspace `default` is not necessarily `A`.
- `P`: actual selected donor root, normally `A`; `S`: its pinned tracked commit
  after the command's declared snapshot. Installed ignored payload is local to
  `P`, not encoded by `S`.
- `D`: frozen desired parent. `--source-at` asserts source tree equality; `--at`
  independently chooses `D`. Equal trees need not mean equal commit identities.
- Existing receiver root `W`, post-initial-snapshot old tip `T`, and newly
  allocated receiving tip `N`. Success is `parents(N)=[D]`, `tree(N)=tree(D)`.
  Current `Plan.desired_commit` changes from `T` to `N`; it is not `D`.
- Frozen auxiliary roots, link ownership and retained local regions accompany
  this binding, separately from tracked membership and native administration.

**Existing source paths need no new interface.** Add/switch use current checkout
or `--from`; CLI resolves caller-relative destination before changing source
context (`cli.rs:781–803`). Omitted `--at` snapshots then pins source `@`;
explicit target-only `--at` pins without that forced snapshot
(`lifecycle.rs:651–683`). Preserve that distinction. Creation invoked from a
registered sibling uses its direct resolved `R`, not copied donor metadata;
primary-local ignored selection still comes from `A/.jwreseed.local.toml`.
Creation link defaults use `inventory.default_name()` separately. Do not silently
move those owners to `P`.

Reseed/prepare already resolve CLI `--from` → primary-local source → verified
primary. Relative local configuration paths are primary-relative. Reseed's donor
belongs to the same repository as its targets; creation `--from` selects the
repository context rather than importing cross-repository bytes.

### The cache-membership bound changes the safe plan

[Graph1](/design/native/graph1.gpt61sxh.md) proves that a **truthful** full-S cache
can absorb an ignored retained local in `tracked(S) \\ tracked(D)` and native
restore can delete it. Matching bytes, mode, size, mtime and unchanged ignore
rules do not supply permission. Final exact D, HEAD/index and clean Git status
can all pass while local preservation fails.

Therefore existing targets keep **equal-subset/reset with no source-state
adoption**. Graph0's one existing-colocated native case supports that route;
graph1's no-adoption control retains the conflicting local and inode. Creation
may use complete source prefill plus source-state adoption because its supplied
source-only leaves are operation-owned, not retained preexisting locals. A
partially copied source or equal subset cannot receive a full-S cache.

A future existing-target adoption optimization would need compatibility between
source/desired membership and actual retained intent: at minimum the exact-path
hazard `retained ∩ (tracked(S) \\ tracked(D))`, plus ancestor/descendant shape
overlap. If “remain untracked” is promised, `retained ∩ tracked(S)` matters too.
Declining that optimization is sufficient now. This is an ownership condition,
not another donor validity walk or recurring source-hash trial.

`tests/reseed.rs:1184–1255` already exercises donor-state adoption manually, but
explicitly says production uses sparse expansion; its retained locals are outside
source membership. Retain this bounded protocol evidence and add a clear
membership-regression counterpart. Its success cannot justify transplanting that
route into production reseed.

- Probe actual JJ flag/backend capability (`jj.rs:362–389`). Replace the absolute
  “0.46+” implication with capability-based wording acknowledging supported
  builds. Before promising pre-mutation refusal for insufficient Git, include
  the Git executable selected by native `git.executable-path`; `worktree add
  --orphan` needs Git 2.42 per inspected upstream, only 2.55 was exercised.

Owner propagation and capability-message correction can start without selecting
new defaults or broad transfer semantics. Joint explicit mode and its precedence
change need product acceptance, but do not depend on a generic framework.

### 2. Existing JW-owned colocated reseed

Files: `src/reseed/engine.rs`, `src/reseed/payload.rs`, `src/cow/transfer.rs`,
small reuse/extraction in `src/ownership.rs`, and `tests/reseed.rs`.

Replace the blanket rejection at `engine.rs:790–795` with a topology binding:
JJ-only or verified **JW-owned linked Git**. Preserve rejection of external-owner,
unrecorded/malformed/replaced Git metadata, mismatched repository/registration,
and other currently unsupported contexts. Existing `validate_owned_at` and its
topology/admin helpers supply useful validation; share that read-only logic with
reseed rather than treating a cleanup function as the new mutation API. Do not
mint ownership merely because a target has a valid gitfile.

Capture/recheck root and `.jj` identity, receiving repository pointer/name/path,
gitfile relationship, private admin identity and common-dir/backlinks/token.
Replace repeated `.git`-must-be-absent check at `1364–1375` with that binding's
verification. Receiving `checkout` operation bytes and HEAD/index may change
through native commands; target identity must not.

Keep sparse/new/equal-prefill/reset at `1427–1568`. Make `payload::outside` admit
only the already-validated root Git boundary at every target call; nested
administration still refuses. `WorkspaceClear` preserves root `.git` **and**
`.jj` in place, never copies either from source. Source omission and source
directory versus receiving gitfile collisions are both preserved. Auxiliary
legacy routing already preserves unselected roots; test this symmetry instead
of replacing it with a broad copier. Explicit clear retains its current authority
over other contents, including `.env`.

Add native Git conformance to completion for this supported topology: ordinary
single parent HEAD at D, complete index consistent with native parent semantics,
intended tracked tree and executable/link properties. Root can have unborn HEAD;
do not invent a commit to “repair” it. Current JW resolves one D even if D is a
merge commit; multi-parent native study results are not a new JW feature. Reuse
native JJ's index/export behavior, never manually copy/reset the index.

### 3. Accepted defaults, help, configuration and output together

After the selected reseed/creation-only boundary is delivered, change the shared
default (or explicit add-only default parameter), help and examples together.
Retain `workspace.colocate=false`, `--no-colocate`, and independent `--no-cow`.
An explicit `--cow` must no longer force JJ-only. `--no-cow` only changes tracked
materialization: selected ignored payload still requires private CoW.

Keep current copy-list precedence: disable > explicit CLI > primary-local >
global > empty; explicit empty stops inheritance. A missing source match succeeds
without deleting a target-only matching root. Inside an actually selected root,
mirror deletion remains authorized. Creation selected-root collisions refuse;
reseed reconciles them. Preserve initial target auto-tracking and subsequent
auto-track-disabled verification, including bookmark coverage of post-snapshot T.

Use existing reports rather than introducing a transfer journal:

- `PLAN ... READY` is **preflight eligibility**, not finished payload. Keep the
  current dry-run warning that snapshots may record changes. Shared source failure
  is not assessed, not READY; blocked members do not trigger refill of a subset.
- Successful creation/reseed says actual topology and selected materialization,
  with CoW fallback reasons in diagnostics. Final success waits for tracked native
  convergence, selected auxiliary work, links and final conformance. A paused,
  skipped or uncertain native phase cannot report whole-command readiness.
- Desired parent D, source S and resulting N must not share an ambiguous “revision”
  label. Old T is preserved native work, not feature contents on the new disk.
  Unknown/unobserved counts stay unknown; no “zero hashing” or all-files-reflinked
  claim follows from retained inode evidence.
- Keep shell path stdout usable; diagnostics belong on stderr. Existing structured
  status enum meanings remain intact; any new structured fields should be optional
  under the project's JSON v1 rule, or deliberately versioned if semantics change.

### 4. Prepare and optional generic adoption stay small

`prepare.rs:115–201` already implements source-only fetch, select an empty child,
sequential configured argv and exact-goal checks. Preserve that behavior and its
explicit “all commands may run again” failure message. Add/switch/reseed do not
implicitly run it. Preparation success certifies its declared source goal/checks,
not durable dependency health or readiness of any receiver. No new configuration
is needed for the recommended native landing.

For later optional continuation, adopt typed work at the JW boundary, not shell
strings or a global registry. Start with coarse joined native segments and existing
payload execution. Save intent/tips and unresolved work only: P/S, W/repository/
topology, D, T where still needed, acknowledged N and phase, frozen transfer/link
policy, remaining payload obligations. Native finish waits for complete tracked
materialization; incomplete children cannot yield readiness.

An unacknowledged native `new D` cannot simply retry: it may already have allocated
N. The narrow contract is explicit refusal pending native-specific inspection or
out-of-band disposition. Do not expose `--resume` until that boundary and the
production transfer adapter are implemented. Current CLI tests deliberately reject
reseed/prepare `--resume`. A saved phase or codec is not an effects journal,
rollback, crash recovery, or exactly-once execution.

The walking specimen's builder and request/ack are reusable design evidence, but
its executor reads complete file bytes and settles exact regular-file content.
Porting it directly would lose JW's required reflink, attributes, literal symlink,
clear/type-transition and permission contracts. A production adapter is separate
work, only needed if finer pauses are selected. Subtree modes can specialize known
listed leaves or preserved regions without changing these product policies.
