## 1. Common semantic types and owners

The following names are a handoff vocabulary, not a demand for one public trait
per row or a final Rust generic signature.

| Type or boundary | Owner and invariant |
| --- | --- |
| `Bindings` | Caller resolves root identities and logical/source/target routes. A target route does not assert existence. Physical observation/preparation coordinates are not logical identity. Missing input is not absence authority. |
| `ProgramDescriptor` | Application fixes program/version, output-affecting parameters, policy, satisfaction and routing interpretation. A restored run cannot silently change these. |
| `PhysicalBatch` | Inspector supplies actual presence and admitted immutable facts, then full local validation. Borrow the delivered `DirectoryPlan`; do not forge generated slots or retain it as saved authority. |
| `Goal` | Program declares an unresolved intended result: ensure a real container, settle a source-file destination, or install a generated file. It survives reobservation changing the physical proposal. |
| `TargetClaim` | Composition establishes the writer/reservation, affected destination region and dependency position. Claims cover ancestor shape and coupled replacement, not just exact duplicate names. A reservation denies competing authority; it is not itself a fresh execution grant. |
| `DesiredFile<Recipe>` | Producer owns explicit generated origin, destination, bytes or reproducible recipe/inputs, desired attributes and satisfaction rule. No fabricated source `Metadata` or mtime. |
| `Frame<Local, Aggregate>` | Driver owns phase, accepted local result, unclosed child suffix, accepted child aggregate, outstanding finish and coverage. Every expanded edge has exactly this recursive owner. |
| `ComponentsState` | Each stateful component has one saved owner for all behaviorally necessary data. A descriptor/label alone does not save mutable producer state. |
| `PendingUnit` / `Ticket` | Driver retains semantic intent, phase/attempt identity and a possible block. Ticket guards acknowledgments within the advancing lineage, not cross-process exactly-once effects. |
| `EntityOutcome<R>` | Declared result and coverage. Satisfied, intentionally retained and abandoned-incomplete differ. Assessment evidence, goal settlement and actual writes use separate counters. |
| `Saved` / `Running` | `Saved` owns future data; `Running` rebinds program, inspector, executor and live resources. Codec accepts only saved data. Runtime grants, file handles and permission guards do not become DTO fields. |

A concrete application can start with this small closed work family:

```rust
enum Work {
    EnsureDirectory { target: Target },
    SettleSourceFile { source: SourceCoordinate, target: Target, rule: FileRule },
    InstallReport(DesiredFile<SummaryRecipe>),
}

enum Request {
    Inspect { ticket: Ticket, node: Node, role: InspectRole },
    Effect { ticket: Ticket, work: Work },
    Done(EntityOutcome<Aggregate>),
}

// Schematic ownership, not new core API:
struct Saved {
    bindings: Bindings,
    program: ProgramDescriptor,
    frames: Vec<Frame>,
    components: ComponentsState, // includes ManifestState::next_ordinal
    pending: Option<PendingUnit>,
    next_ticket: u64,
    final_outcome: Option<EntityOutcome<Aggregate>>,
}
```

Use ordinary functions or a concrete `Program` plus `match Work` dispatch. Executable
code is supplied again on bind. A finite descriptor dispatcher becomes useful
only when independently versioned operation families actually need it; it does
not solve input admission, ownership or satisfaction. A provider becomes useful
when virtual directories participate in **child discovery**, not merely because
a postorder summary is generated.

## 2. Progress, acceptance and failure

### One ordered owner

Use native-name DFS with directory phases **before → assess → children → finish**.
A regular leaf can be a single settlement phase. Parent creation gates its child
assessment/effects. Finish waits for accepted child outcomes. Only closure removes
the active child edge and folds its result into its parent.

1. Before work settles prerequisite container/routing obligations. Failure admits
   no dependent children. A created container can remain if assessment later fails.
2. Assess accepts one complete immediate batch or none. Successful lowering installs
   local data once and retains owned selected children, including source-only
   directory interiors. Clean physical batches are accepted too.
3. Children keep the active edge at the front until that child closes. Executor
   units do not recurse over edges also represented by the driver.
4. Finish derives a value or selected work. Effectful finish remains outstanding
   until acknowledged or explicitly abandoned incomplete; it cannot run in a free
   stack pop merely because no physical differences remain.
5. Close checks the candidate fold/component update, then installs it and retires
   the edge as one in-memory transition. No supported pause splits that transition.

“Fold once” means once **in this advancing state lineage**. Accepted local data is
not re-added on retry; executor success alone does not independently fold into
every ancestor. Reusing/forking an older snapshot can repeat work. No history of
removed child frames or completed effects is required.

Current opaque sync remains coherent: paired walk owns matched edges and sync
owns one-sided/replacement interiors. It just has a coarser pause boundary. The
chosen specimen cannot call recursive `apply_plan` for a child and also expand
that child's interior itself. A future nonrecursive sync adapter, or a sync-owned
explicit continuation, can be considered after this contract is demonstrated.

### Two limits, neither a latency promise

`Limits { assessments, effects }` accepts zero in either field. Stop at the next
required unit whose class is exhausted; do not jump over an ordered dependency.

| Charge | Exact meaning |
| --- | --- |
| One assessment | One attempted immediate-directory inspection, clean/empty/failed included. Charge before I/O. Scheduled-directory structural checks belong to the attempt; initial command binding checks are separately documented. |
| One effect | One dispatched, joined, resource-closed attempt to settle a container, leaf or finish obligation, including failed attempts and satisfaction no-ops. It is **not** one namespace write. |
| Zero | Pure push/fold/closure and deterministic recipe derivation. An effectful finish still needs an effect allowance. |

Ordinary `drive` does not voluntarily return between dispatch and acknowledgment:
the host joins work and closes staging/permission scopes first, then acknowledges
and considers the next limit. An owned request can be examined externally without
running it. A restored **unacknowledged** request remains unresolved, even if its
effect might be visible; it must be re-examined, not accepted by assumption.

Neither cap bounds listing width, leaf bytes, syscalls, memory, event count or
elapsed time. `PlanWalk::next()` is not an assessment unit: it can cross many clean
directories. Opaque recursive apply cannot advertise child-sized accounting by
counting its outer call as one small effect.

### Retry and skip

Persist the goal and required finish values, not an old physical `Action` or live
prepared grant. On error, retain the unresolved phase and accepted prefix. Retry
reobserves the inputs/routes needed to settle **that goal**. A created directory
can now exist; an install/finish that errored after rename can already satisfy the
goal. Neither case licenses guessing success or replaying a stale action.

For general existing `Visitor` semantics, current facts for one leaf may be
insufficient: the decision was directory-batched. A future adapter must expose
`InspectRole::RefreshPending`, charge that complete fresh assessment, refinalize
policy, and select only the unresolved scheduled unit. Its refreshed batch is not
another accepted logical expansion or aggregate contribution. Newly seen siblings
do not silently join the saved schedule. Drop invocation-local grants at pause;
reconstruction may require another charged refresh. A refreshed retention decision
is not satisfaction of a stricter desired goal.

The first specimen instead uses a declared fixed desired-file program, not an
arbitrary Visitor adapter, so direct current file/output checks suffice. Those
reads are explicit parts of its effect attempt, not concealed directory scans.

`skip_blocked_unit()` has phase-specific scope:

- Before/failed initial assessment: abandon that scheduled entity/subtree.
- Leaf: abandon that leaf only; keep accepted siblings.
- Finish: abandon that finish; keep accepted local/child results and close incomplete.

Mark **all active ancestors incomplete immediately**. Leave visible effects alone.
After a skipped child, only a program explicitly permitting partial results may
run a partial finish. Native readiness cannot be asserted from incomplete children.
Reject wrong-ticket, wrong-phase and duplicate consumed acknowledgments without
an ever-growing deduplication set. Validate a candidate state before fallible folds
or component updates can partly advance it.

## 3. Desired satisfaction, claims and fact acquisition

These are compatible seams, not one replacement for physical comparison.

**Physical evidence stays physical.** Core still compares regular-file type/size/
mtime and literal symlink text, with structural directories. A desired-byte goal
can require work despite an equal physical stat key. Such work goes through the
new program's typed request, **not** an illegal `Action::InstallLeaf` on an equal
slot. Keep physical difference counts separate from goal outcomes.

**Satisfaction is an explicit predicate over desired inputs and observed target.**
`Satisfied / Unsatisfied / Unknown` is useful vocabulary. Unknown never means
equal. Caller choices include more observation, unconditional installation,
deferral/refusal, digests, or validated receipts. Output-affecting parameters and
producer version belong to reproducibility/compatibility. The specimen selects
exact bytes and regular-file kind, with no requested metadata attributes; that is
not a generic default. A nondeterministic producer must retain its produced body
or immutable reference rather than silently rerun to a different desired result.

**Resolve competing destinations before their effects.** Physical/generated
same-name ownership, two-to-one mapping and leaf/ancestor conflicts cannot be
resolved by enumeration order. Predeclared claims, disjoint owned regions or an
explicitly documented late-conflict boundary are distinct designs. For the first
slice choose disjoint reserved output; do not generalize it to a complete mapping
policy. Preservation denies both physical and generated writers unless separately
authorized. An unfinished/skipped producer supplies no desired-absence deletion
authority. Existing output at its one declared destination is not a second desired
owner; it is the actual target to assess.

**Demanded facts remain compatible with this model through explicit acquisition.**
The observer owns I/O; pure policy/production consumes supplied inputs. Presence,
exclusion, unknown kind and unsupported kind stay distinct. Accessors never fetch
missing data. A later sparse API can stage name admission → required kind → union
of comparison/policy demands → selected execution demands, caching one acquired
`Metadata` when stat supplies both kind and attributes. Generated desired fields
stay outside physical facts.

Do not block the specimen on that API migration. Use today's full-fact immediate
inspector as the honest **full-demand compatibility mode**. Its late
`Facts::metadata() -> &Metadata` cannot be satisfied by a partial payload. A later
compatibility-first demand entrypoint can share internals; moving Update/Seed/Prune
decisions from overrideable late adapters to terminal early exclusion is **not**
automatically semantics-preserving. Omitting physical comparison also changes the
evidence contract; call it NotAssessed, not Equal or unsupported.

Retain current facts only through their immediate useful consumer. Reuse freshly
acquired execution attributes in one invocation where possible; pause may require
reacquisition. Do not serialize `std::fs::Metadata`, listings or borrowed names by
assertion. Retained child coordinates need owned lossless names/backing storage.
An execution adapter adding deferred acquisition must state whether errors still
precede every effect in the immediate batch or now occur per smaller effect unit.
No change may quietly weaken today's whole-batch observation/validation boundary.

## 4. Next commission A: component builder and real walking specimen

**Deliverable:** new `examples/walk/` nested crate and README, library construction
plus focused CLI/process tests. Leave core/sync and `examples/cursor` unchanged.
Use component grouping, not a framework: bindings, full inspector, concrete copy
program, typed executor, manifest component and optional transport. A constructor

An adequate construction seam is this small (schematic, not required spelling):

```rust
let saved = Saved::start(bindings, program.descriptor(), manifest.initial_state())?;
let mut running = Running::bind(saved, program, inspector, executor, manifest)?;
running.drive(Limits { assessments: 2, effects: 2 })?;

// Another process binds decoded `saved` to newly supplied implementations.
```

The manifest implementation is rebound; its mutable ordinal lives in saved
component data, not in a freshly defaulted runtime object. A bind validates data/
component compatibility; initial filesystem binding and each active attempt's
current route checks are separate operations.

### Fixed demonstration semantics

- Linux/Unix tiny writable trees; existing real, disjoint `source`, `target` and
  exclusively reserved `reports` roots. Cursor files are outside all three.
  Source is good/stable; callers own concurrency, nonhostile topology and routing.
- Desired input is source-present regular files and real directories. Descend
  matched and source-only directories. Preserve target-only subtrees; refuse
  admitted links/specials and directory/leaf collisions. No deletion or type
  replacement, arbitrary remapping, native metadata, reflink requirement or
  restrictive-mode relaxation. Regular-file-to-regular-file refresh is allowed.
- Copy **real source bytes**, settling each file by current exact bytes and real
  regular-file kind. Do not claim sync's mtime/mode preservation or chmod repair:
  desired attributes are unspecified. One equal-byte settlement is a no-write
  effect attempt, not another physical comparison result.
- Ensure each absent target container as its own effect. New-directory modes use
  the documented ordinary creation/umask behavior. A container is not complete
  until descendants and its finish are settled. No live permission lease crosses
  a pause; permissions outside this writable-fixture scope remain separate work.
- Each directory finish renders accepted settled-leaf count, incomplete flag,
  frozen label and manifest ordinal. It measures declared progress, **not a fresh
  post-effect inventory or proof that source/target roots are equal**. Partial
  finishes are explicitly allowed and labeled in this specimen.
- Reports use a fixed injective, length-checked basename mapping in the reserved
  root: root `root.txt`; nonroot `dir-<hex(native relative bytes)>.txt`. All are
  direct children, so there is no output ancestor collision. Reject an
  unrepresentable route before that entity's effects. The tiny fixture fits.
  This is a demo mapping/namespace, not a general output placement policy.
- Install copied/generated bytes through same-parent private staging and rename;
  close descriptors and owned staging before acknowledgment. Refuse an unexpected
  target shape. No write-through of an existing inode, recursive `apply_plan`,
  effects in Visitor, automatic prune, durability transaction or exactly-once
  publication claim. Cleanup errors are reported, not hidden by a skip.

The manifest has saved `{ label, next_ordinal }`, initially 1. Derive a recipe with
the current ordinal; advance it only on accepted finish settlement. Retry uses
identical desired bytes. A skip consumes no ordinal; an uncertain visible report
can therefore contain an ordinal reused by the next accepted finish. This counter
is not a globally unique artifact ID. It tests genuinely stateful component
construction without replaying finished outputs as history.

### Exact fixture and numeric process gates

```text
source/d/a = "one"       target/ empty       reports/ empty
source/d/b = "two"
```

With no root ensure effect and no extra root finish prerequisites:

| Invocation | Limits and required saved boundary |
| --- | --- |
| 1 | `assessments=2, effects=2`: assess root; ensure `target/d`; assess `d`; settle `a`; pause before `b`. `d` aggregate 1, root aggregate 0, ordinal 1. |
| 2, fresh process | `assessments=0, effects=1`: settle `b`; pause before effectful `d` finish. `d` aggregate 2, root aggregate 0, ordinal 1. No ancestor relisting. |
| 3, fresh process | `assessments=0, effects=1`: settle `d` report; retire/fold `d`; pause before root finish. Root aggregate 2, ordinal 2. |
| 4, fresh process | `assessments=0, effects=1`: settle root report; terminal complete-in-domain result 2, ordinal 3. |

Also require `effects=0` to stop before a ready finish; `0/0` may drain only ready
pure transitions. Failed attempts consume their own class. Report attempted units,
accepted goal results and current-invocation actual namespace writes separately.
Do not save a per-file write history merely to demonstrate counters.

### Focused acceptance tests

1. The four gates above use real separate executable invocations and preserve
   label, pending phase, both component states and byte-lossless coordinates.
   Validate saved aggregates/coverage, not just final files.
2. Fail before `b`, then after its rename is visible. Retry retains accepted `a`,
   settles current `b` once, and the second case needs zero new file installations.
   Repeat before/after visible `d` report; ordinal/root fold advance only on ack.
3. Skip blocked leaf and blocked finish separately. Accepted siblings remain;
   all ancestors become incomplete; visible unaccepted artifacts are not undone
   or counted as accepted. Partial reports say so. Test duplicate/wrong ack.
4. Empty equal physical roots still reach generated root finish. Run label A,
   then a **new run** B, then B: changed desired bytes install despite unchanged
   physical inputs; the last run proves a report no-op. A resumed run rejects
   changed descriptor parameters instead of silently becoming a new run.
5. Target extras remain. Type collisions and malformed routes refuse before the
   affected effect. For equal stat keys but differing file bytes, the explicit
   desired-byte program still settles desired bytes without rewriting core diff.
6. A library test binds restored state to freshly constructed executable objects;
   another returns the same saved form without any codec. No required codec or
   native dependency enters core. Terminal resume performs no tree inspection.

Only specimen-focused nextest, clippy and format checks are needed. Keep fixtures
tiny and owned; no JJ commands, broad suite reruns, workload imports or benchmark.
The scratch tests are useful precedent, not substitutes for these new gates.
